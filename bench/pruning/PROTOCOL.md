# Candidate-pruning measurement protocol

Fixed before the first timed run of the pruning campaign (Phase 1 of
`perf/gpu-candidate-pruning`). Phase 0's measurement of what is at stake:
`bench/results/2026-10-05-candidate-waste/FINDINGS.md`. The configs are
generated by `bench/consolidation_matrix.py::build_pruning_matrix` and run by
`bench/runner.py --mode pruning`.

## What is compared

The row-split miner (route C) at its default kernel dispatch, three arms:

| arm | `apriori(...)` | what the K≥3 counting kernels do |
|---|---|---|
| `off` | `prune_apriori=False` | count every candidate the prefix groups generate (the tree before this work) |
| `prune` | `prune_apriori=True` | skip a candidate whose (k−1)-subset is missing from the previous level: per candidate in the per-candidate kernel and the sparse CSR kernel, per 32×32 tile-pair in the tiled kernels; in a free-set run the index is the free level, so this also drops the candidates that cannot be free |
| `infer` | `prune_apriori=True, use_generator_pruning=True` | `prune`, and write the count of a candidate with a non-free (k−1)-subset as the minimum of its subset counts instead of counting it (complete-lattice runs only) |

Every arm mines the same itemsets with the same counts; a skipped candidate
keeps its index and its count slot.

## Box and budget

2× RTX A4000 16 GB (sm_86), Ryzen 5 5600X 6C/12T, 46 GB RAM: the Phase 0 box.
Budget ≤ 3 GPU-hours (process wall × devices the config uses); the campaign
runs with `--max-gpu-hours 3.0`, and the owner is asked before more is spent.

Every config pins `POLARS_MAX_THREADS`, `RAYON_NUM_THREADS`, `MKL_NUM_THREADS`
and `OMP_NUM_THREADS` to 6, restricts one-GPU configs to device 0 with
`ET_MINER_DISABLE_NCCL=1`, exports `NCCL_P2P_DISABLE=1`, and records each
level's time split (`bench/level_split.py`). Nothing else runs on the box
during the campaign.

## Workloads and configs

| id | dataset | min_support | max_length | arms, 1 GPU | arms, 2 GPUs |
|---|---|---|---|---|---|
| smoke, deepk, skew, or003, or002 | as in the consolidation protocol | | — | off, prune, infer; free-sets: off, prune | — |
| dsl | deep_sparse_large (20M) | 0.015 | — | off, prune, infer; free-sets: off, prune | off, prune, infer |
| oom2ml3 | oom_regression (500K) | 0.00003 | 3 | off, prune, infer | off, prune |
| sk2ml3 | stress_k2 (2M) | 0.000015 | 3 | off (1 rep), prune | prune (1 rep, not judged) |
| deepk-esco, or002-esco | as deepk / or002, `sparse_from_k=3` | | — | off, prune, infer | — |

stress_k2 has no non-free pair (Phase 0), so `infer` cannot differ from
`prune` there and is not run. The `off` arm of sk2ml3 runs once (≈ 9 minutes);
its range is that one value.

## Repetitions and order

Fresh process per config with the runner's warm-up; 3 reps, rep-major; within a
rep the long configs (dsl, oom2ml3, sk2ml3) run after the short ones; the
single-rep configs run in rep 0 only. Cells are median [min, max].

## Metric

`wall_s` of the timed call. The Σ K≥3 level time and the level split are
recorded and reported as evidence, never as the deciding metric.

## Decision rule (the consolidation protocol's, applied mechanically)

1. **Signature mismatch or logged fallback** disqualifies the arm in that
   regime: report it as (must-fix) and decide nothing on that point until it
   is fixed.
2. **Winning a regime**: an arm's median is ≥ 10 % below the best other arm
   of the same decision, the two [min, max] ranges do not overlap, and it saves
   ≥ 1 s absolute.
4. **A partial winner** stays only if a dispatch rule selects it from facts
   known before the level runs (words per row, generated candidates, size of
   the previous level, free VRAM); implement it and record the crossover. If
   none exists, keep the arm with the best geometric-mean wall time across
   regimes and record what it loses and where.
5. **Ties everywhere**: keep whatever serves the most routes with the least
   code; break remaining ties on peak VRAM.

A regime is one row of the table above at one GPU count (a free-set run and an
ESCO run are their own regimes). A config that errors or times out cannot win.

## Decisions

- **DP-P: the subset test.** `prune` against `off`, in every regime.
  - `prune` wins a regime and loses none: `prune_apriori` defaults to `True`;
    `False` stays as the opt-out the comparison and the tier chain use.
  - `off` wins a regime: rule 4.
  - Ties everywhere: rule 5 removes the test again; `prune_apriori` goes back
    to raising.
- **DP-I: count inference on the GPU.** `infer` against `prune`, in the
  complete-lattice regimes.
  - `infer` wins a regime and loses none: the GPU route honours
    `use_generator_pruning` (default unchanged, `False`; flipping it is the
    owner's call and outside this protocol).
  - `prune` wins a regime: rule 4.
  - Ties everywhere: rule 5 removes the GPU inference; `use_generator_pruning`
    is refused on the GPU routes, as it is on SON.

## Correctness gate (before the campaign, and on the final tree)

`uv run ruff check src tests bench`; `uv run pytest -q -m "not slow"`;
`uv run pytest tests/test_tier_equivalence.py` (with the new legs);
`uv run pytest -q -m "gpu and slow"`; `uv run pytest -q -m "gpu and multigpu"`;
`uv run python bench/selfcheck.py`. The runner's per-group signature check
must pass across all arms.
