# Route-optimizations measurement protocol (phase A: O1, O2, O3)

Fixed before the first timed run of phase A of `bench/optimizations/SPEC.md`.
The configs are generated by `bench/consolidation_matrix.py::build_optimizations_matrix`
and run by `bench/runner.py --mode optimizations`, the calibration by
`--mode optimizations-calibration`; the K=2 crossover sweep is
`bench/k2_crossover.py`. Phases B and C get their own protocol.

## What is compared

The row-split miner (route C, transactions input) at its default dispatch and
`prune_apriori=True`. Three decisions, each an A/B against one shared `base`
arm. Every arm pins all three knobs, so `base` is the tree as merged (0b2f068)
with one exception (amended 2026-10-05, before the first timed run, on the
owner's decision): O2 needs every GPU to write the same entries, so the K≥3
kernels (tiled, per-candidate, sparse CSR) write an inferred candidate on every
GPU, its inferred count on the GPU that writes them and 0 on the others, where
the merged tree left it unwritten on the others. The results are identical; the
cost is one int32 write per inferred candidate per further GPU.

| arm | `ET_MINER_K2_KERNEL` | `ET_MINER_REDUCE` | `ET_MINER_ESCO_MATERIALIZE` |
|---|---|---|---|
| `base` | `dense` | `dense` | `recount` |
| `rows` (O1) | `rows` | `dense` | `recount` |
| `compact` (O2) | `dense` | `compact` | `recount` |
| `reuse` (O3) | `dense` | `dense` | `reuse` |

- `dense` K=2: today's kernels (tiled, per-candidate sub-chunks, or fused on one
  GPU beyond one chunk). `rows` K=2: each row adds 1 to every pair of its
  frequent columns, in the same dense int32 pair array, from a per-shard CSR of
  frequent-column positions; a pair array beyond one chunk is counted by ranges
  of j.
- `dense` reduce: the NCCL sum of whole int32 chunk arrays. `compact` reduce:
  every GPU gathers the entries its K≥3 kernels counted or inferred (the same
  entries on every GPU: the skip decision is a function of the shared index)
  into one buffer in the same order, the buffers are summed, and the threshold
  filter maps survivors back to their candidate indices. K=2 and levels without
  a subset index keep the dense reduce.
- `recount` ESCO materialization: `count_csr_gather` for the new offsets, then
  `write_csr_gather`. `reuse` (amended 2026-10-05, before the first timed run,
  on the owner's decision): the offsets come from the count pass: on one shard
  the exclusive scan of the survivor counts; on several shards each further
  shard's partial counts, read from its count array after the reduce (which
  leaves them unchanged), and the first shard's length is the global count
  minus theirs. A survivor that is 0 on every further shard is gather-counted
  as under `recount`: under count inference an inferred count is written on
  the first GPU only, so its per-shard split is unknown. The write checks
  every tidset against its slot and raises on a mismatch.

Unset, each knob keeps today's behaviour until this protocol decides. Every arm
mines the same itemsets with the same counts.

## Box and budget

2× RTX A4000 16 GB (sm_86, `NCCL_P2P_DISABLE=1`), Ryzen 5 5600X 6C/12T, 46 GB
RAM: the pruning campaign's box. Budget ≤ 3 GPU-hours (process wall × devices
the config uses) for the calibration, the sweep, the campaign and the final
check together; the campaign runs with `--max-gpu-hours` set to what is left,
and the owner is asked before more is spent. Estimate: ≈ 1.5 GPU-hours (the
pruning campaign's 137 runs took 0.58).

Every config pins `POLARS_MAX_THREADS`, `RAYON_NUM_THREADS`, `MKL_NUM_THREADS`
and `OMP_NUM_THREADS` to 6, restricts one-GPU configs to device 0 with
`ET_MINER_DISABLE_NCCL=1`, and records each level's time split
(`bench/level_split.py`, with the new phases `k2_input` and `count_rows` for
O1, `compact` for O2, `transition` and `materialize` for O3). Nothing else runs
on the box during the calibration, the sweep or the campaign. Tracked files
are frozen from the first timed run to the last (the runner stamps every row
with the tree's digest).

## Calibration (before the sweep; counted in the budget; not judged)

One run of `dsl-esco` (`sparse_from_k="auto"`) per GPU count on `base`, capped
at 600 s. If it completes, the row joins the campaign; an out-of-memory or a
cap hit drops it and is recorded. Reason: O3's measured stake on deepk-esco and
or002-esco is 0.08–0.10 s ("other" in the pruning level split), below rule 2's
1 s floor, so O3 can only win where ESCO levels are large.

## K=2 crossover sweep (the rule-4 input for O1)

The dispatch fact is `r = Σ_rows C(len, 2) / (pairs × words)` over the frequent
columns, known after K=1. On the campaign workloads (computed on the datasets):

| workload | F | Σ_rows C(len, 2) | pairs × words | r |
|---|---|---|---|---|
| oom2ml3 | 30,000 | 98,735,918 | 3.52e12 | 2.8e-5 |
| sk2ml3 | 35,000 | 562,968,354 | 1.91e13 | 2.9e-5 |
| or002 | 2,614 | 40,906,330 | 1.95e9 | 0.021 |
| or003 | 2,145 | 36,504,277 | 1.31e9 | 0.028 |
| smoke | 118 | 906,884 | 6.48e6 | 0.14 |
| deepk | 112 | 36,506,151 | 9.71e7 | 0.38 |
| skew | 118 | 62,213,394 | 1.08e8 | 0.58 |
| dsl | 85 | 1,546,715,052 | 1.12e9 | 1.39 |

The workloads leave r between 3e-5 and 0.02 empty, so the sweep places the
crossover. Synthetic K=2-only problems (`max_length=2`, every item frequent),
1 GPU, N = 1M rows, F ∈ {100, 300, 1,000, 3,000, 10,000, 30,000} items, row
length L ∈ {5, 10, 20, 40}, items uniform; one line with Zipf(1.0) item
popularity at L = 20; two points at N = 4M to check that r, not N, predicts.
Per point one process, a warm-up, then 3 interleaved reps of each pinned
kernel; the K=2 level time is the median. `r*` is the geometric mean of the two
adjacent r values where `t_rows / t_dense` crosses 1 on the uniform lines; if
the Zipf line crosses lower, `r*` is the lower value.

|---|---|---|---|---|---|

| dsl | deep_sparse_large (20M) | 0.015 | — | base, rows | base, rows, compact |

| oom2ml3 | oom_regression (500K) | 0.00003 | 3 | base, rows | base, rows, compact |
| sk2ml3 | stress_k2 (2M) | 0.000015 | 3 | base, rows | base, rows, compact |

Short two-GPU rows for O1 and O2 are left out: their levels take milliseconds,
so rule 2's 1 s floor cannot be met; the tier chain covers their correctness.

## Repetitions and order

Fresh process per config with the runner's warm-up; 3 reps, rep-major; within a
rep the short configs run first, then the ESCO configs, then dsl, oom2ml3,
sk2ml3. Cells are median [min, max].

## Metric

`wall_s` of the timed call. The level split (K=2 level time for O1, the K≥3
`reduce` + `compact` time for O2, `materialize` for O3) is recorded and
reported as evidence, never as the deciding metric.

## Decision rule (the consolidation protocol's rules 1, 2, 4, 5, applied mechanically)

1. **Signature mismatch or logged fallback** disqualifies the arm in that
   regime: report it as (must-fix) and decide nothing on that point until it
   is fixed.
2. **Winning a regime**: an arm's median is ≥ 10 % below the other arm of the
   same decision, the two [min, max] ranges do not overlap, and it saves ≥ 1 s
   absolute.
4. **A partial winner** stays only if a dispatch rule selects it from facts
   known before the step it changes runs; implement it and record the
   crossover. If none exists, keep the arm with the best geometric-mean wall
   time across regimes and record what it loses and where.
5. **Ties everywhere**: keep whatever serves the most routes with the least
   code; break remaining ties on peak VRAM.

A regime is one row of the table above at one GPU count. A config that errors
or times out cannot win.

## Decisions

- **DP-O1: the K=2 kernel.** `rows` against `base`, in every regime.
  (Amended 2026-10-05, before the first timed run, on the owner's decision.)
  - The sweep places `r*` inside its grid and `rows` wins a regime: the
    dispatch is implemented (rule 4 with `r` and `r*`, `rows` below `r*`) even
    when `rows` loses no regime. Reason: rule 2's 10 % bar can hide a loss of
    seconds on a long workload (dsl, r = 1.39: `rows` about 1.7 s slower at
    K=2 in an unwarmed run), and a tie must not make the slower kernel the
    default there. The campaign checks the dispatch: the arm it picks must not
    lose a regime (rule 2) to the other; a regime it misclassifies is a
    (must-fix) finding and the decision waits for it.
  - No crossover inside the grid, `rows` wins a regime and loses none: `rows`
    counts K=2 wherever the miner has the transactions; `dense` stays for
    `bitvecs=` input and as the pin.
  - No crossover inside the grid and both win regimes: the sweep contradicts
    the campaign; a (must-fix) finding, and the decision waits for it.
  - `base` wins and `rows` wins none, or ties everywhere: the row-wise kernel
    is removed.
- **DP-O2: the multi-GPU reduce.** `compact` against `base`, in the two-GPU
  K≥3 regimes (dsl, dsl-infer, oom2ml3, sk2ml3).
  - `compact` wins a regime and loses none: the K≥3 levels with a subset index
    reduce compacted; `ET_MINER_REDUCE=dense` stays as the pin.
  - `base` wins a regime: rule 4. The step `compact` changes is the reduce, so
    the counted fraction of a chunk (known after the count, before the reduce)
    is an admissible fact.
  - Ties everywhere: rule 5 removes the compacted reduce.
- **DP-O3: ESCO materialization.** `reuse` against `base`, in the ESCO regimes.
  - `reuse` wins a regime and loses none: `reuse` replaces `recount`; the
    knob goes, and the gather-count pass stays only for the survivors `reuse`
    recounts. (Amended 2026-10-05, before the first timed run, on the owner's
    decision.)
  - `base` wins a regime: rule 4 (facts: shard count, survivors, the parent
    tidset lengths).
  - Ties everywhere: rule 5. Both arms serve the same routes, so the code
    decides: the lines of `src/` (Python and CUDA, without comments and blank
    lines) that only that arm needs. Expected outcome without dsl-esco: a tie
    on time.

## Final check (after the decisions are implemented; counted in the budget; not judged)

One rep of every regime with the knobs unset (the decided defaults). The
signatures must match the campaign's; a mismatch is (must-fix).

## Correctness gate (before the sweep, and on the final tree)

`uv run ruff check src tests bench`; `uv run pytest -q -m "not slow"`;
`uv run pytest tests/test_tier_equivalence.py` (with the new legs:
row-wise K=2 pinned on 1 and 2 GPUs and with forced chunks; the compacted
reduce on 2 GPUs plain, forced chunks and with count inference; ESCO `reuse`
on 1 and 2 GPUs, with and without count inference);
`uv run pytest -q -m "gpu and slow"`; `uv run pytest -q -m "gpu and multigpu"`;
`uv run python bench/selfcheck.py`. The runner's per-group signature check
must pass across all arms.
