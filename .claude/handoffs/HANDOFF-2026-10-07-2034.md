## Decisions & Rationale
- **One array engine on the CPU route**, with Polars only reading the input. This was the owner's decision on the Phase 0 report. `sparse=` there warns (`DeprecationWarning`) and is ignored; SON still uses it.
- **NumPy floor stays `>=1.20`.** Popcount uses `np.bitwise_count` when present and a 16-bit lookup table otherwise.
- **`polars>=2.0.0`** at the owner's request. The `collect` calls that relied on the old in-memory default now name it.
- **Measured dispatch constants** (top of `cpu_miner.py`, each with its evidence):
  - `PROJ_MIN_SUFFIXES = ((2048, 40), (inf, 80))`, from `bench/cpu/l3_crossover.py`.
  - `GRAM_BITVEC_RATIO = 3.0`: bitvector K=2 ran at 0.61–0.69× of the Gram's time at work ratios 1.7–2.7, and 6.3–38.6× slower at 7.1–175.
  - `HEAVY_GROUP_WORK = 2M` pairs × words.
  - `PARALLEL_GRAM_WORK = 5M` pair occurrences.
- **Staying within the 25 % memory rule took:**
  - an int32 indptr, so scipy keeps int32 indices;
  - CSR mapping in 500K-entry chunks into a preallocated output;
  - bitvectors built from CSR rows (no CSC);
  - chunked K=1 counting;
  - projection gathers without a data copy.
- **The EA arm times `itemsets_from_transactions`**, without tids or rules, and leaves out the tuple conversion. The ET-Miner arm times the `apriori()` call with the data already loaded.

## Dead Ends
